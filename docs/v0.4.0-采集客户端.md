# v0.4.0 采集客户端

需求依据：[确定双平台采集客户端的共同边界与交付范围](https://github.com/litianc/w2f-cli/issues/40#issuecomment-5990432333)及[确定端云落库与飞书投递的恢复规则](https://github.com/litianc/w2f-cli/issues/41#issuecomment-6008946998)。本文件记录当前交付的操作方法与验证边界，完整需求决策保存在相应决策票。

## 当前交付：本地文本采集与端云上传

`python -m client` 调用外部 `ordered_sync_v1` 读取器，把启用后出现的普通文本持久保存到独立待上传队列。当前 CLI 每次执行一轮有限快照扫描；还不是已安装的 macOS 后台客户端。

- 每个状态目录绑定一个源账号和读取器，可启用多个群；各群有自己的本地读取进度和固定快照分页状态。
- 启用成功时以读取器观测到的快照上界建立起点；先前历史不入队。再次启用同一群保留原起点与积压。
- 一页消息和该页读取进度在同一事务中提交。后续页失败时，已保存的页保留；重启先完成原快照，再由下一轮处理新快照。
- 同一群、同一源消息在本状态库中只入队一次，事件 ID 入队时生成并持久保存。重复扫描和重启不会重建事件 ID。
- 源群错误、编号乱序、快照上界变化、分页停滞或读取器不可用时，该页不入队且不推进读取进度；状态提供失败原因。
- 待上传容量以保存的源消息 JSON 的 UTF-8 字节数计，默认 64 MiB。超过上限时整页保留在源端，报告 `queue_full`；不删除积压、不跳过消息。数据库索引/WAL 等额外磁盘占用不在该逻辑配额内，真实磁盘写入失败仍按事务回滚并报告本地状态错误。
- `kind_name=text` 且 `local_type=1` 的普通文本受支持。遇到媒体或其他类型报告 `unsupported_message`，保留该页等待后续实现；这不是缩减 v0.4.0 最终内容范围。
- 采集只写本地队列；不读取飞书凭据，不调用旧 Worker 的发送路径。云端确认和飞书回执不会由本地读取游标推定。

## 命令

使用 Python 3.12。内核仅依赖标准库；外部平台读取器按其自身要求安装。以下参数需使用独立测试环境的真实值；不要把占位值当作可执行配置，也不要使用 main 的状态目录。

```sh
# 状态目录必须是尚不存在的独立绝对路径；不读取 main 配置。
python -m client --state-dir /absolute/path/to/v040-client-state init \
  --reader /absolute/path/to/reader --account SOURCE_ACCOUNT

# 读取源快照并确认该群启用；之前历史不采集。
python -m client --state-dir /absolute/path/to/v040-client-state enable --talker GROUP_ID

# 运行一轮；没有常驻进程，也没有自动上传。
python -m client --state-dir /absolute/path/to/v040-client-state collect
python -m client --state-dir /absolute/path/to/v040-client-state status

# 只读查看待上传事件。输出包含消息正文，应作为私有数据处理。
python -m client --state-dir /absolute/path/to/v040-client-state pending --limit 100 --after 0
```

`init` 可指定 `--page-size`（1–1000）和 `--max-pending-bytes`。M1 已增加 `connect`、`upload`、`retained` 与 `prune`；按事件持久确认后保留 7 天，已确认副本单独核算。凭据配置、授权、查询与清理操作见[端云接入操作](v0.4.0-端云接入操作.md)。

所有命令输出 UTF-8 JSON。`collect` 任一群失败即返回非零退出码，并在 `streams[].error_code` 给出原因；其他可采集群仍可完成本轮。状态中的 `read_cursor` 只表示本地保存进度，`snapshot_high` 表示尚未结束的扫描上界。`upload_implemented=true` 与 `delivery_implemented=false` 明确标识当前能力。

源数据库重建导致编号回退时会停止并要求核对；编号未回退的源库替换并不能仅凭该契约完整识别。此版本的事件身份是本地状态库内的身份，不能用于证明跨设备或重建状态库后的全局去重。M1 已校验设备、账号、群和授权版本；完整源库识别与换机接续尚待实现。无法验证接续时不允许宣称正常无缺口切换。

## 验证

`tests/test_client_collection.py` 通过真实 CLI 子进程和外部模拟读取器，核对启用起点、分页、稳定事件 ID、并发重复启动、容量保护、异常页回滚、读取器故障和续采。测试不接触真实微信数据。

`verify-w2f` 的 `messages.py collect RUN` 使用同一模拟消息源驱动本内核，并保留两次进程调用的状态与待上传事件作为重启证据。它与 `messages.py drive RUN` 使用的旧单机 Worker 数据库各自独立。详见[模拟消息验证](../.agents/skills/verify-w2f/features/synthetic-messages.md)。
