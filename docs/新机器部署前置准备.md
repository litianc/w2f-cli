# 新机器部署前置准备

这份清单用于让 Codex 在新的 macOS 电脑上部署 W2F CLI。首次启动不会自动发送消息。

## 交给 Codex 的执行提示词

```text
请部署并检查 W2F CLI：https://github.com/litianc/w2f-cli

按顺序执行：
1. 检查 macOS、Python 3.10+、Git、ffmpeg；缺少普通工具时安装或告诉我。
2. 项目放到 ~/Documents/Code/w2f-cli，执行：
   python3 -m venv .venv
   .venv/bin/python -m pip install -r requirements.txt
3. 检查 lark-cli；缺少时安装官方版本并执行 lark-cli --version。
   遇到扫码、登录或权限审批时停下来告诉我。
4. 检查 rion-wechat-cli 和微信读取授权，确认完整数据库可读；只有通知预览时停下。
5. 检查完整分页和媒体本地路径能力；找不到读取器安装来源时停下。
6. 执行：
   .venv/bin/python -m unittest discover -s tests -q
   .venv/bin/python scripts/check_public_tree.py
7. 执行 .venv/bin/python -m agents.manage serve，把管理台链接发给我，先不要启动 Worker。
8. 在管理台选择微信群、飞书群和 Profile，完成预检查。Secret 不得进入对话、Git 或日志。
9. 把绑定、同步起始位置和检查结果展示给我；我说“确认启动绑定”后再启动。
10. 启动后执行 .venv/bin/python -m agents.manage status，报告 Worker、心跳、游标和积压。

不要配置开机启动或自动重启。遇到困难只报告失败步骤、原因、已完成内容和需要我做的一件事。
```

## 用户需要做的事情

1. 安装并登录微信。
2. 按 Codex 提示完成微信读取器扫码或系统授权。
3. 在飞书开放平台发布机器人并开通消息、群访问和媒体权限。
4. 完成 Codex 提供的飞书授权链接。
5. 确认微信群、飞书群、Profile 和同步起始策略。
6. 明确告诉 Codex“确认启动绑定”。

## 成功标准

- 两条测试命令通过，`lark-cli --version` 可执行。
- 微信读取器报告完整数据库可读。
- 管理台预检查通过，Worker 为 `alive: true`，心跳持续更新。
- 凭证不出现在 Git、日志、网页响应或聊天内容中。

如果是旧机器迁移，必须先确认旧 Worker 已停止；不能让两台机器同时处理同一绑定。
