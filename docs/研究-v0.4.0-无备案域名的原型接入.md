# v0.4.0 无已备案域名时的原型接入研究

日期：2026-10-04（Asia/Shanghai）。对应[核实无已备案域名时的云端原型接入选项](https://github.com/litianc/w2f-cli/issues/45)。本文记录一手资料、实测证据和技术建议；正式选择由部署决策票保存。本研究未安装软件、配置网络或部署服务。

## 当前方向与条件

用户最新选择是**公网 IP + 端口**，并明确 **13000 已被占用，不能使用**；先前 SSH 私有联调的选择已被替代。按当前条件，少量受控测试可评估“自建 CA 签发 IP 证书 + 客户端明确信任”的 HTTPS 入口；公开 CA 的 IP 证书也已存在，但本机公网80/443验证条件尚未证实。两者都只是传输和身份验证方式，不构成备案豁免。

当前候选主用映射为 `120.133.41.177:13040 → 服务器:3040`，备选为 `:14040 → :4040`。主会话于本日实测：

| 检查 | 证据 |
| --- | --- |
| 启动前占用 | ss和Docker端口列表未见3040/4040占用 |
| 两组公网映射 | 临时HTTP响应器分别返回随机挑战值；公网curl均退出0、TOKEN_MATCH=True |
| 清理 | 临时响应器关闭，ss确认两端口均无监听，SSH退出0 |

上述证据来自主会话的有界无业务数据探针，证明两对端口当时可达；**没有部署HTTPS，也不能推广成全部“1xxxx→xxxx”映射规则**。真正部署前仍需复查占用。13000不再作为候选。

## 备案与网络技术应分别判断

工信部《非经营性互联网信息服务备案管理办法》第五条明确把通过域名和仅通过IP地址访问的网站都纳入相应定义；不能从“没有域名”推导无需备案。阿里云接入规则也明确，其中国内地节点通过非80/443端口提供域名访问，仍须备案。当前服务器的实际地域、接入商及其可办理备案的资格尚未核实，不能仅按IP猜测。[工信部规定](https://www.miit.gov.cn/gyhxxhb/jgsj/cyzcyfgs/bmgz/xxtxl/art/2024/art_84a0cfa0ebd049bbbe751dca9a008e56.html)、[阿里云备案服务器检查](https://help.aliyun.com/zh/icp-filing/basic-icp-service/user-guide/icp-filing-server-access-information-check)

所以，换高位端口、安装证书、SSH/Tailscale或其他隧道，都不能作为“免备案”的法律判断。个人开发调试、受控试用、面向公众提供服务的实际范围应向接入商/主管部门确认；本笔记只确定网络选型。采用公网IP入口并不解决这项待核实条件。

## 候选方式比较

| 方式 | 对当前原型的作用 | 条件与取舍 |
| --- | --- | --- |
| 公网IP+高位端口，自建CA HTTPS | 符合用户最新方向；不依赖公开CA签发 | 每台采集设备和管理员浏览器须建立明确信任；需要证书分发/轮换；仍须核对备案与接入规则 |
| 公网IP+公开CA HTTPS | 浏览器/客户端可使用公有信任链 | Let's Encrypt支持IP证书，但需控制IP并满足公网80或443验证，且自动续期要求高 |
| SSH本地转发，云端仅loopback | 单Mac开发接入最小；保留真实云端落库和飞书出站链路 | 需维护隧道；用户目前已改选公网入口，可保留为排障候选 |
| Tailscale Serve私有HTTPS | 多台受控设备可访问私有ts.net地址 | 各端加入tailnet并设置访问规则；中国内地网络可达性尚未测；没有备案豁免结论 |
| 大陆域名备案后公开服务 | 适合后续正式公网入口 | 先确认提供方能办理接入备案、地域与主体条件 |
| 整体迁至香港节点 | 可另行评估公开域名接入 | 阿里云规则下香港/海外节点无需其ICP备案；须核对实际提供方条件、成本/延迟和数据安排，不把海外前置代理视为大陆源站豁免 |

## IP HTTPS：少量受控测试的技术建议

Caddy支持本地CA签发证书，`tls internal`可明确选择内部签发方；客户端只有信任该CA后才能正常验证。技术上可用于IP站点；实施时证书应覆盖实际访问IP的IP SAN，TLS入口绑定已验证的内部端口，再通过公网高位端口访问。这不依赖ACME或DNS挑战。[Caddy Local HTTPS](https://caddyserver.com/docs/automatic-https#local-https)、[Caddy tls internal](https://caddyserver.com/docs/caddyfile/directives/tls#internal)

建议客户端优先使用项目专属CA信任配置，保持证书链、有效期与IP匹配校验；管理员浏览器需显式安装/信任相应CA。若采用证书/公钥固定，必须同时设计固定值分发和轮换；不能用关闭TLS校验或长期忽略浏览器警告代替。CA私钥仅留在受控签发端，公开证书可分发；不把CA私钥、飞书凭据或客户端token打进镜像。这些是拟议实现要求，尚未生成或安装证书。

该方案允许验证真实 macOS 客户端→云端→飞书测试群，保留已定“推送codex/v0.4.0且测试通过后自动发布”。仍需API token/管理员登录及用户隔离；有HTTPS不等于已有应用鉴权。

Let's Encrypt自2026-01正式提供IPv4/IPv6证书，IP证书采用160小时短期有效期。HTTP-01只能走公网80；TLS-ALPN-01走公网443；DNS-01不能验证IP。已通13040/14040不等于可完成这些挑战，因此目前不能承诺公开CA路径立即可用。[IP证书公告](https://letsencrypt.org/2026/01/15/6day-and-ip-general-availability)、[验证方式](https://letsencrypt.org/docs/challenge-types/)

## 私有接入候选的事实边界

SSH的`-L`将本机监听端口经加密通道转到服务器地址/端口；显式绑定本机127.0.0.1并让云端服务只监听loopback，可供单Mac开发访问。云端计算、存储和飞书发送仍在服务器；只是访问路径变成隧道。本次没有配置或测试转发，服务器是否允许相应转发权限仍需验证。[OpenSSH -L](https://man.openbsd.org/ssh.1#L)

Tailscale Serve把本机服务提供给tailnet内设备，受访问规则约束，支持如`https://device.tailnet.ts.net`代理到本机HTTP服务；它与公开互联网发布的Funnel有不同访问范围。本场景的私有候选只讨论Serve。[Tailscale Serve](https://tailscale.com/docs/features/tailscale-serve)

Tailscale HTTPS使用其ts.net名称和DNS验证来申请证书，不要求用户先购买域名；机器名/完整证书域名会进入公开证书透明度记录，但服务访问仍受tailnet限制。当前没有安装Tailscale，没有验证登录、直连或中继在本机/服务器的可用性，不能预先承诺国内连接质量。[Tailscale HTTPS](https://tailscale.com/docs/how-to/set-up-https-certificates)

## 后续需落实

- 确认接入商、真实地域和当前受控试用/未来公众服务的备案要求；IP和端口本身不给出答案。
- 在部署票确定主用13040→3040和自建CA方案，复查端口；13000保持排除。
- 完成证书生成/明确信任、应用鉴权和真实HTTPS测试，再验证端到端发送与CI/CD发布恢复；本次只验证了HTTP映射。
- 公网域名备案或整体迁香港作为后续独立选择，不阻碍当前协议/存储/客户端代码设计。
