# 图片与表情资源修复

## 2026-09-27 根因与实现

普通图片的本地资源为微信 V2 DAT，原解码器只支持旧式单字节 XOR。新增 `agents/media_images.py`，支持明文图片、旧 XOR、V1 与 V2 分段解码；校验文件长度、AES padding 及图片解码结果。缺少参数、分段损坏和解码失败分别记录错误，不能将占位发送成功视为图片成功。

macOS 的 V2 参数推导默认关闭。只有用户授权后，才在本机运行配置中设置 `macos_image_key_derivation: true`；Worker 根据本条媒体路径所在账号，读取已知 kvcomm 缓存文件名，在内存中派生候选并验证图片。不会扫描进程、修改微信、打印或持久化参数，也不扫描其他工具的私有密钥目录。不支持此布局或候选无效时保留失败项，不能保证所有微信版本均适用。

参考格式与参数说明：[V2 文件结构](https://github.com/jackwener/wx-cli-again/blob/main/src/attachment/decoder/v2.rs)、[macOS 参数派生](https://github.com/jackwener/wx-cli-again/blob/main/src/attachment/image_key/macos.rs)。本项目独立实现，未安装或执行上述工具。

表情发送记录可能只有 md5，没有 CDN 地址。Worker 先检查消息 content/text 中的 XML、已有下载地址与读取器返回的本地资源；仍不可用时，通过现有微信 CLI 在同一群内检索同一 md5 的原始记录，最多读取 100 个匹配结果。仅接受群身份与摘要一致的候选，并在有有效摘要时校验下载内容。资源不可得、查询失败、下载失败、摘要不符和解码失败有独立错误码；不在日志中输出原始下载地址。

表情继续保持最大 200×200、等比缩小、不放大。GIF、动态 WebP 等多帧资源输出 GIF，单帧输出 PNG；限制下载大小、帧数和总解码像素。历史无匹配、地址失效且本地没有可读资源时仍可能失败，会保留人工处理记录。

## 2026-09-28：语音与人工重试

原语音没有出现在读取器普通媒体路径中，而保存在已授权消息数据库旁的 VoiceInfo 表。新增只读 voice-resource 扩展：按群与服务器消息 ID 匹配；仅数据库服务器 ID 为零时，允许群、local_id、create_time 三项严格匹配。不同候选冲突、任一分片不可读或音频头不符时停止，不猜测资源。

可选 [pilk](https://pypi.org/project/pilk/) 在独立子进程解码 SILK，FFmpeg 转 Opus。中间文件创建时权限 0600，完成后清理；不把语音内容、解码参数或凭证写入 Git。

原失败语音已在本机转换：Opus、单声道、约 2.87 秒，ffprobe 校验通过。没有对外发送；真实补发等待明确授权，飞书客户端播放尚未验收。此证据不等于全部语音格式均通过。

人工补发不再被历史累计失败次数永久锁死：每次明确人工重试开启最多三次尝试的新一轮，累计次数仍保留；重复点击正在处理的任务不重置轮次。补发回复原占位；发送结果不确定时转人工核验，不盲重发。
