# 微信读取器契约（Reader Contract）

Worker 通过 `WECHAT_READER` 环境变量（或运行配置的 `wechat_reader` 字段）调用一个**外部可执行入口**读取微信消息。任何平台、任何实现，只要满足本契约即可接入，核心同步逻辑零改动。

- macOS：`rion-wechat-cli` + `scripts/install_reader_sync.py` 注入的 `sync-page` 扩展
- Windows：[WeChatDataAnalysis](https://github.com/LifeArchiveProject/WeChatDataAnalysis) 本地 API + `integrations/wda_reader.py` 适配层（`scripts/install_wda_reader.py` 生成垫片）

## 命令与输出形状

除持续输出 JSONL 的 watch-changes 外，命令输出**单个 JSON 对象到 stdout（UTF-8）**；失败时 `"ok": false` + `error.message` + 非零退出码。

### `sync-page` — 有序增量分页

```
<reader> sync-page --talker <群ID> --after-local-id <N> --limit <M>
                   [--through-local-id <H>]
                   [--page-after-time <T> --page-after-local-id <L>]
```

```json
{"ok": true, "data": {
  "contract": "ordered_sync_v1",
  "messages": [ {行}, ... ],
  "through_local_id": <扫描时可见的最大 local_id>,
  "has_more": <bool>,
  "next": {"time": <create_time>, "local_id": <n>} | null
}}
```

**不变式（Worker 会强制校验，违反即保留游标停止补发）：**

1. `data.contract === "ordered_sync_v1"`——缺少契约视为读取器不支持完整分页，禁止补发。
2. 每行 `talker` 必须等于请求的 `--talker`；`local_id` 满足 `after < local_id <= through_local_id`。
3. `local_id` 严格单调递增；`has_more=true` 时 `next` 必须相对上一页推进。
4. `through_local_id` 是**扫描时刻的源快照上界**，同一次扫描的各页保持一致。

### 消息行字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `talker` | string | 群 ID（如 `example@chatroom`） |
| `local_id` | int | 群内单调递增序号，**游标的唯一真相** |
| `server_id` | string | 源服务器消息 ID（媒体定位用，可空） |
| `sender_wxid` | string | 发送者微信 ID |
| `sender` | string | 发送者显示名（解析不了就回填 wxid，Worker 有实名兜底流程） |
| `local_type` | int | 原始消息类型；成员事件必须为可信系统消息 10000，普通文本中的 XML 不可触发成员变更 |
| `kind_name` | string | 消息类型（下表） |
| `text` | string | 正文；引用/转发保留原始 XML（Worker 嗅探 `<refermsg`/`<recorditem`） |
| `create_time` | int | Unix 秒级时间戳 |
| `forward_items` | array | 可选；`forward_chat` 预解析的转发结构（不预挂也能靠 XML 兜底） |

**kind_name 集合**：媒体 `image / video / file / voice / audio / emoji / sticker / media`；转发 `forward / forward_chat / merged_forward / chat_history / history`；专用 `channel_video`（视频号）；其余一律 `text`。无对应分支的类型由适配层降级为 `text` + 全角方括号占位（如 `[转账]`、`[消息已撤回]`）。

### `resolve-chat` — 搜索会话（管理台选群用）

```
<reader> resolve-chat <关键词> --type-filter group --limit 30
```

```json
{"ok": true, "data": {"candidates": [{"name": "...", "username": "example@chatroom"}]}}
```

### `media` — 单条消息的本地媒体资源

```
<reader> media --talker <群ID> --local-id <N> [--server-id <S>] --include-local-paths true
```

```json
{"ok": true, "data": {"resources": [{"local_paths": ["<绝对路径>", ...]}]}}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `local_paths` | array | 真实存在的绝对路径；先选未标记为缩略图的可用资源，同等质量内再按体积选择；原图与缩略图并存时不因缩略图体积更大而误选；原图全部无法暂存/解码时重查可用缩略图并标明降级 |
| `thumbnail_only` | bool | 可选；`true` 表示只找到预览级资源（如 CDN 原图已过期），Worker 会在镜像消息上附「原图未同步」提示 |

路径必须**真实存在**（Worker 会 `is_file()` 校验后直接上传）；找不到资源返回空 `resources`，Worker 走占位 + `media_jobs` 人工补发，**不得伪造路径**。图片类资源应优先原图（Windows 适配层对图片先带 `fetch_remote` 请求 WDA 拉 CDN 原图，失败才回落缩略图）。

## 实现注意

- stdout 必须 UTF-8（Windows 默认代码页会损坏中文）。
- 读取器不可达时输出结构化错误并退出非零，让 Worker 进入 `disconnected` 阶段，而不是静默返回空页（会被误判为「没有新消息」）。
- 读取器不负责发送、不持有飞书凭证、不修改微信数据——只读。
- 参考实现：`integrations/wda_reader.py`（Windows，纯标准库）；macOS 端为 rion 读取器 + `integrations/reader_sync.py` 扩展。

语音消息可附可选字段 `voice_transcript`（非空文本）。Worker 优先按“姓名：转写文字”发送；没有转写时走音频文件/占位链路，不在热路径主动触发 Whisper。消息来源类型仍记录为 `voice`。

## 可选能力

- `watch-changes --poll-interval 1`：持续输出 JSONL 变更提示。macOS 只比较数据库和 WAL 元数据，不逐秒解密数据库。提示只唤醒正常有序扫描，不直接推进游标；不支持时仍有定时扫描兜底。
- `voice-resource --talker <群ID> --local-id <N> [--server-id <S>] --create-time <T>`：返回 data.contract=voice_resource_v1，包含 talker、local_id、extension、base64。只供进程间资源传递，不记录完整输出。调用方核对群、消息、大小和音频头；只读已配置账号对应的语音库，分片不可读或候选冲突时明确失败。
- `members <群ID> --limit 10000 --offset 0`：成员同步需要完整快照，data.chatroom_id 等于请求群，total 等于唯一有效 members[].username 数量，无截断或后续分页。不能将缺失记录推断为退群。WDA 响应缺少明确群身份或总数时转人工核验，不回退到其他账号/读取器。

运行配置的 wechat_reader 同时用于同步分页、群名与成员读取，优先于环境变量默认值。


自动群名跟随只接受唯一匹配稳定群 ID 的 `nick_name`，或契约中的真实群名 `name`。仅有 `display_name` / 备注不构成真实群名证据，必须显示失败并保留目标名称，不能拿个人别名修改飞书群名。


文章分享可附 `article` 对象，字段为 `title`、`url`、`description`、`cover_url`。已解码的完整 HTTP(S) URL 原样保留，不裁剪查询参数。Worker 同时解析 Rion 原始 type-5 XML 的相同字段（实体和 CDATA 由 XML 解析器处理）；封面与头像等辅助地址不会混作正文链接。WDA 保留已提供的文章元数据，并持久化供离线续传及人工补图。无元数据的纯文字链接只按文字发送，不引入网页抓取。
