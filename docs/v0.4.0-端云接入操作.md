# v0.4.0 M1：文本端云接入

M1 支持本地文本队列 → HTTPS → Postgres 存档与持久确认。存档与唯一投递任务一起提交；投递任务保持 `pending`，绑定的 `delivery_enabled` 默认为 false。云端发送器属于 M2，当前操作不发送飞书。

## 客户端和认证

在 v0.4.0 独立工作目录运行 `python -m client --state-dir /独立绝对路径 ...`。先 `init --reader /读取器绝对路径 --account 源账号`，再 `enable --talker 源群`；启用时从当前源上界开始，不导入历史。`status` 返回设备 ID、每群的 stream ID，提供给管理员。

管理员创建 JSON 配置（仅存私有目录）：

```json
{
  "user_id": "<管理员生成的 UUID>",
  "device_id": "<client status 的 device_id>",
  "source_account": "<与客户端 init 一致>",
  "bindings": [{
    "id": "<管理员生成的绑定 UUID>",
    "stream_id": "<client status 的 streams[].id>",
    "talker": "<已授权源群>"
  }]
}
```

在已配置私有数据库秘密的云端容器内执行：

```sh
python -m cloud.manage provision --spec-file /私有配置/provision.json --credentials-file /私有配置/device.json
python -m cloud.manage show --kind device --id '<device UUID>'
```

也可让 `--spec-file -` 从标准输入接收 JSON。凭据文件必须是新文件，按 0600 创建；命令只输出设备 ID，不打印令牌。容器的 `/tmp` 可用于暂存，导出后删除；持久保管应使用独立私有目录。现有 Compose 可用 `exec -T app` 执行这些命令。不要把凭据放进命令参数、Git、issue 或测试证据。

一个源账号当前只能注册一台设备；数据库唯一约束拒绝重复注册，包括已停用设备。M1 没有实现正常/强制换机流程，不能通过再次 provision 绕过交接。一个用户可注册多个不同源账号。每个绑定固定设备、群和 stream ID；stream ID 是这次源流的身份，授权版本独立保存。

把设备凭据和受信任 CA 安全交给对应客户端后：

```sh
python -m client --state-dir /独立绝对路径 connect --credentials-file /私有配置/device.json --url https://服务器:端口 --ca-file /私有配置/ca.crt
python -m client --state-dir /独立绝对路径 collect
python -m client --state-dir /独立绝对路径 upload
python -m client --state-dir /独立绝对路径 status
python -m client --state-dir /独立绝对路径 retained
python -m client --state-dir /独立绝对路径 prune
```

设备凭据必须与已有本地设备/账号匹配。HTTPS 验证 CA 和主机名，禁用重定向与代理环境变量；管理员 Basic 密码不能用于设备上传。Mac/Linux 私有文件权限被检查；Windows 文件 ACL 和真机运行仍须在 Windows 交付阶段验证。

`collect` 与 `upload` 都是有界命令，当前没有自动启动的常驻程序。一次 upload 每群至多一批（100 条且总请求不超过 2 MiB），按本地序号上传；单事件上限 256 KiB。未获确认的事件继续保留原 ID，下次 upload 重试。一群失败记录在 `streams[].upload_error`，不阻止该轮其他群上传。采集文本超过协议上限时保留待处理，不跳过。

## 查询、停用与恢复副本

- 设备令牌可请求 `GET /api/v1/session` 和 `GET /api/v1/messages/{event_id}`；消息查询限定为认证所属用户。`POST /api/v1/events` 使用 `w2f-text-ingest-v1`，协议见 `w2f_protocol/ingest.py`。不接受客户端自报用户归属。
- 受限管理命令 `show --kind user|device|binding|message --id UUID` 查询；`disable --kind user|device|binding --id UUID` 停用。停用设备同时增加授权版本。所有授权变更与接收提交共享数据库事务锁，停用生效后新上传不能越过校验。
- 同事件、同规范化载荷返回原保存事实；改载荷、回退流序号或源 local_id 报冲突。每条确认包含事件 ID、载荷摘要、绑定与云端恢复代次，只确认实际保存项。
- 客户端原 `w2f-client-v040-1` 状态自动事务迁移到 v2，保留事件、采集游标和待上传数据。旧客户端不能打开 v2 状态。
- 第一次持久保存完整确认后保留副本 7 天；重复确认不重新计时。`retained` 查询本地保留/待核对项。`prune` 先核对云端代次，再删除满 7 天且非待核对的已确认项；离线不清理。待上传配额与已确认副本分别显示；空间不足时保留状态并报错，不提前清掉恢复副本。

## 数据库升级与恢复代次

`cloud.server` 在开放 HTTP 监听前执行版本化、事务化、仅增量的 schema 迁移。当前 schema 为 1；重启可重复执行。M1 不改变三服务 Compose 拓扑。原管理入口的状态响应保持兼容。

原型阶段云端写入使用一个事务级 advisory lock，明确串行化接收与授权变更；吞吐扩展随后再做。事件同时写入存档与投递任务，事务退出成功后才产生 HTTP 完整确认。

恢复旧备份时，管理员先停止入口与发送，再恢复数据库，执行 `python -m cloud.manage new-generation`，核对后才重新开放入口。该命令更换恢复代次并暂停所有绑定投递，不重建或重发任务。客户端发现代次变化后保留全部本地副本为待核对状态，停止自动采集/上传/清理。恢复缺失数据与未知飞书结果的人工核对工具尚未交付，M1 不自动合并旧副本。

验证入口见 [verify-w2f 端云配方](../.agents/skills/verify-w2f/features/text-cloud-e2e.md)。自动化只使用一次性环境；真实原型部署与飞书联调继续按实施计划的 M3 推进。
