# v0.4.0 部署与发布

本环节交付独立云端运行入口、HTTPS、管理员认证、持久化基础和自动发布链路。对应[部署决策](https://github.com/litianc/w2f-cli/issues/39)。采集、镜像和存档的功能验收沿用需求地图中的后续事项。

## 隔离边界

| 资源 | 本地开发 | 服务器原型 |
| --- | --- | --- |
| Compose 项目 | w2f-v040-local | w2f-v040-prototype |
| 入口 | https://127.0.0.1:13040 | https://120.133.41.177:13040 → 内部3040 |
| 状态与凭据 | 独立开发工作树的 .v040-local | /opt/w2f-v040/state |
| 数据库与媒体 | 各项目专属 postgres/media 卷 | 各项目专属 postgres/media 卷 |
| 数据库/API 端口 | 仅容器网络 | 仅容器网络 |
| 日志 | 各服务最多3个10MB文件 | 各服务最多3个10MB文件 |

不使用公网13000。main 的用户配置目录、SQLite、媒体、后台和进程均不读取、不迁移、不挂载。新服务不导入单机 agents 模块。CI 使用随机项目名、临时凭据和临时数据卷，并在结束时只清理自己的资源。服务器既有数据库与Caddy不变；原型使用独立容器。

## 本地入口

需要 Python 3.12 和 Docker Compose。所有命令在 `codex/v0.4.0` 开发工作树执行。

```sh
python3.12 -m venv .venv-cloud
.venv-cloud/bin/python -m pip install -r cloud/requirements-test.txt
.venv-cloud/bin/python -m cloud.runtime init
.venv-cloud/bin/python -m cloud.runtime up
```

打开 https://127.0.0.1:13040 。用户名 `admin`，密码在 `.v040-local/secrets/admin_password`。CA证书在 `.v040-local/pki/ca.crt`，须显式信任；不要忽略证书错误。命令行验证用 `curl --cacert .v040-local/pki/ca.crt https://127.0.0.1:13040/health/ready`。本脚本不自动修改系统信任库。

停止仅当前环境：`.venv-cloud/bin/python -m cloud.runtime stop`。保留数据库和媒体卷；禁止为了清理开发环境而全局执行 Docker prune。

运行既有浏览器回归时设置独立缓存，避免Playwright安装器清理其他环境的浏览器：`PLAYWRIGHT_BROWSERS_PATH="$PWD/.v040-local/browsers" PLAYWRIGHT_SKIP_BROWSER_GC=1 .venv-cloud/bin/python -m playwright install chromium`，并将相同变量传给 `python -m qa.run`。

## TLS与认证

当前使用本原型专属CA签发包含公网IP SAN的服务端证书。CA私钥仅由运维保管，容器只挂载服务端证书与私钥；客户端分发的是CA公开证书。每个环境单独生成管理员密码与数据库密码。密码作为文件挂载，不写进镜像、Git、CI日志或HTTP响应。

`/health/live` 与 `/health/ready` 是公开的最小探针；管理页面和 `/api/status` 要求HTTP Basic认证，经HTTPS传输。健康检查实际连接专属数据库并检查媒体卷可写。服务版本通过认证后的状态接口确认。对外传输不允许跳过TLS验证。

服务端证书有效期180天；重新运行同一环境的 `cloud.runtime init` 保留CA和密码、更新服务端证书，随后重新创建 gateway 使新证书生效。当前没有无人值守证书续期任务。公开CA的IP证书另需验证公网80/443条件；不能从高位端口可达推导已具备公开CA签发条件。

## CI/CD

`.github/workflows/cloud-v040.yml` 在推送 `codex/v0.4.0` 后运行隔离回归、云端接口测试和真实容器的TLS/认证/持久化/失败回滚测试。通过后将已测试的linux/amd64镜像作为短期GitHub artifact交给发布job，经SSH发送至原型服务器。

此路径不依赖私有镜像仓库拉取令牌。仅部署job读取四个专属Secrets：`V040_DEPLOY_KEY`、`V040_SSH_KNOWN_HOSTS`、`V040_DEPLOY_HOST`、`V040_DEPLOY_PORT`。PR不会进入部署job。SSH主机密钥固定校验，不使用动态信任，也不复用用户root私钥。

服务器专属账号 `w2f-v040-deploy` 不属于docker或sudo组，只能通过受限命令执行 `deploy <完整commit SHA>`、`status`、`rollback`。接收方检查归档只能包含指定W2F镜像、平台及版本标签。CI串行化，同一服务器另有文件锁防并发。

## 发布与恢复

服务目录 `/opt/w2f-v040` 由root管理：Compose、Caddyfile与发布脚本作为基础设施单独更新，应用发布只更换镜像。发布前要求至少3GiB可用空间；已有成功版本时先进行数据库备份，保存到 `state/backups/`。本版没有破坏性数据库迁移。

新镜像必须通过Compose健康检查和带证书校验的HTTPS状态检查，且报告预期commit。失败时恢复上一个健康镜像并再次验证；首次发布失败则停止API/网关，保留数据库与卷供排查。镜像回滚不等于数据库回滚，备份恢复应独立操作。`state/releases.json` 仅在新版本验证成功后更新。

基础设施首次准备：先在隔离环境生成服务状态，将状态、Compose、Caddyfile、release.py、provision.sh和专用公钥放入 `/opt/w2f-v040`；确认端口3040空闲，再以root执行 provision.sh。初始化时使用 `--environment v040-prototype --project w2f-v040-prototype --public-ip 120.133.41.177 --bind-ip 0.0.0.0 --port 3040`，服务器环境文件中的state路径必须是实际服务器绝对路径。
