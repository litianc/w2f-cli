# W2F 产品终局 Spec

> 状态：v2（2026-10-04 更新 v0.4.0 云端服务原型范围）
> 来源：grilling 产品终局讨论（2026-09-22 ~ 09-24）及 v0.4.0 wayfinder 需求讨论（2026-10-04），已定决策均经用户确认。
> 变更规则：本文档记录「定下来的方向」；推翻已有决策时在「关键决策记录」中补一行，不静默改写。

## 北极星原则

**原型产品阶段——速度与可迭代性最重要。** 一切重机制（账号体系、计费、合规工程、SLA 保障、自动运维）都推迟到「被验证需要」时才建；先用最小实现换取真实反馈，再决定投入。

## 愿景与定位

让微信群聊安全、实时、完整地流动到飞书，并沉淀为可长期保存的对话资产。

产品形态演进：**单机镜像工具 → 小圈子云端服务 → 对外 SaaS**。

两条主线价值：

1. **镜像**：微信消息近实时同步到飞书群（跨平台存续、可搜索、可协作）；
2. **存档**：消息与媒体长期记录，成为家庭/团队的对话资产库。

## 三阶段路线

### 阶段 1 · PoC（已完成，2026-09）

Windows 微信读取（WeChatDataAnalysis 适配层）+ 飞书发送全链路验证。Worker、管理台、媒体管线、SSE 实时唤醒（端到端 6-8 秒）、实名映射、离线续传全部跑通；双群实测；读取器契约 `ordered_sync_v1` 文档化；双平台（macOS/Windows）CI 与发布方针确立。

### 阶段 2 · 单用户生产长稳（当前阶段）

**验收口径：连续 4 周，双群并行（测试群 + 一个真实低风险群），指标：**

- 零丢消息（游标连续无跳变）
- 媒体投递成功率 ≥ 95%
- 端到端时延 < 10 秒（实时唤醒链路）
- 无人工干预持续存活；异常可从管理台发现

**消息类型分级：**

| 级别 | 类型 | 处理 |
| --- | --- | --- |
| P0 一等公民 | 文字、图片（原图优先）、链接卡片、表情包、引用/回复、转发聊天记录、文件、视频 | 完整还原 |
| P1 尽力而为 | 语音（转写优先，失败回落音频文件）、视频号、小程序卡片、@某人（文本提示） | 有则更好，不阻塞验收 |
| P2 明确不做 | 名片、位置、转账、红包、拍一拍、撤回提示 | 保持现状文本占位，零投入 |

**守护边界（边界修订）：** 打开最小守护集——Windows 计划任务开机自启 + worker 崩溃自动拉起。原「不装开机自启、不做异常自动重启」的项目边界由此修订；仍不做更重的进程管家。

真实核心群（工作主力群）在验收通过、阶段 3 方向明确后再切换。

### 阶段 3a · 小圈子 SaaS（原型期）

**服务对象**：家人/团队，约 10 人级，半托管（管理员即运维者）。

**架构**：CS——本地采集客户端（macOS / Windows，通过各自读取器采集微信）+ 云端后台（管理端、飞书发送、存储、长期记录）。

| 议题 | 决策 |
| --- | --- |
| 部署 | 原方案为家庭设备 + 内网穿透；v0.4.0 正按用户要求评估指定云服务器及 CI/CD 自动发布，实际部署方案以部署决策票为准 |
| 数据立场 | 全云端：消息明文上云 + 云端发送（体验优先）|
| 存储 | Postgres 存消息（永久）；媒体按 md5 去重落磁盘（永久）；不做自动清理 |
| client | macOS / Windows 两端均纳入开发，当前先开发和实测 macOS；Windows 既有打包方向为 PyInstaller 单 exe + 内置引导，macOS 交付形式待定；安装向导为后期打磨 |
| 账号 | 无自助注册；管理员手动开户，一用户一 client token |
| 飞书凭证 | 成员各自自建飞书应用，Secret 托管云端（跨租户问题被「各自自建」天然化解） |
| 通信 | 数据面：client 单向出站推送 + ack 断点续传（云端先落库再 ack，ack 后推进游标，复刻现有回执机制）；管控面：轻量轮询（约 30 秒） |
| 数据迁移 | 不迁移单机版数据；云端从零建档，实名映射体系（人员/身份/确认流）云端重建 |
| 成员数据权利 | 轻量基线：绑定创建时生成说明文字，由发起人发进群告知全体成员；任何成员可退出（停止该群镜像 + 删除已存数据 + 回执确认）；保留「谁、何时被告知」记录 |

**3a 毕业条件（进入 3b 的前置）**：≥ 2 个外部真实用户群稳定运行 1 个月，标准沿用阶段 2 指标。重大事故定义：消息丢失、连续 24 小时以上不可用、任何形式的数据外泄——发生任一条，计时重来。

**并行策略（2026-10-04 修订）**：阶段 2 长稳与 v0.4.0 云端原型并行。v0.4.0 在独立分支和工作目录内开发，范围扩展到真实采集客户端 → 云端 → 飞书测试群；配置、数据、测试资源、本地管理后台入口和运行进程均与 main 隔离，保留 main 的现有运行环境。

#### v0.4.0 已确认范围

- **版本目标**：云端服务原型，验证真实采集客户端 → 云端 → 飞书测试群的端到端链路。
- **客户端**：macOS 和 Windows 两端均纳入本版开发；当前只有 macOS 实测条件，先开发 macOS 端。Windows 的实际运行验收需在取得对应条件后完成。
- **管理方式**：由管理员集中管理试用者；数据从第一版起按用户隔离。
- **存档体验**：提供最小消息历史浏览、按群和时间筛选、附件查看能力。
- **开发隔离**：独立配置、数据库、游标、媒体、日志、备份、测试资源和后台入口；不迁移或复用 main 的运行状态。具体隔离方案和验收条件由需求地图继续明确。
- **飞书测试隔离**：使用独立飞书应用和独立测试群，不复用 main 的测试投递目标与应用配置。
- **部署候选**：优先评估用户指定、可经非默认公网 SSH 端口访问的云服务器，并调查端口转换和 CI/CD 自动发布可行性；服务器检查与正式部署分开，具体方案尚待决策。
- **接入方式**：当前没有已备案域名，用户选择公网 IP + 独立端口；不使用已占用的公网 `13000`。本版计划使用公网 `13040` → 服务器 `3040`，该映射已用临时随机响应验证，测试监听已关闭；HTTPS、身份认证和应用尚未部署。公网直连替代此前 SSH 私有联调方案，SSH 仍用于运维与发布；证书信任及接入商备案要求仍需落实，完整决策以[部署决策票](https://github.com/litianc/w2f-cli/issues/39)为准。
- **自动发布触发**：向 `codex/v0.4.0` 推送代码后，测试通过即自动发布到原型服务器；部署实现与 main 的工作流和运行环境独立。
- **内容范围**：[确定 v0.4.0 首版镜像与存档的内容范围](https://github.com/litianc/w2f-cli/issues/38#issuecomment-5977953762) 已于 2026-10-04 决策完成，消息类型、首次采集起点及附加同步能力的完整结论以该票的决策记录为准。

本版的具体部署环境、客户端边界、端云协议细节及交付验收门槛通过 [v0.4.0 云端服务原型：需求与决策地图](https://github.com/litianc/w2f-cli/issues/37) 继续明确。阶段 3a 的长期毕业条件不自动视为 v0.4.0 原型的发布门槛。

### 阶段 3b · 对外商业 SaaS（远期，门槛制）

**全部门槛满足才启动，缺一不动：**

1. 3a 毕业（≥ 2 外部群 × 1 个月稳定）
2. 隐私立场重审：全云端明文方案的合规评估（必要时转向端到端加密 / 本地数据面架构）
3. 账号体系（注册/找回/计费）与成员自助数据导出入口
4. 飞书平台统一应用可行性（企业资质 + 商店审核）
5. 部署形态评估：迁移云主机（家庭设备不承载付费用户），规格与成本模型
6. 微信读取依赖（WDA 为第三方项目）的稳定性评估与风险预案

## 代码关系

单机版（main 分支）**永久保留**，同时就是未来 SaaS 本地 client 的内核——读取器契约 `ordered_sync_v1` 即读端与发送端的解耦点；SaaS 增量只有两块：云端管控面、client ↔ cloud 通信层。单机版功能不因 SaaS 化被砍。

## 非目标（Out of scope）

- P2 消息类型的具体实现（名片/位置/转账/红包/拍一拍/撤回的富还原）
- 3a 阶段的自助注册、计费、客服体系
- 数据自动清理/过期删除（永久留存是产品价值）
- 重型进程管家、K8s 级部署、云端全文检索（明文上云方案下自然获得，不另建）

## 开放问题

- 3b 商业模式（免费增值 / 订阅 / 买断）——3a 毕业后再议
- 3b 云主机规格与迁移方案（Postgres + 媒体整体搬家一次）
- 内网穿透选型（frp / Tailscale / 自建）
- 语音转写的 Whisper 模型分发方式
